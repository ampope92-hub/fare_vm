Our fare readers run their fare rules as FVM-2 images, and the back office needs its own interpreter so a disputed journey can be replayed away from the device. The machine sheet is `/app/spec/FVM2.txt`. The project is `/app/fvm`: the Free Pascal source lives in `/app/fvm/src` with `/app/fvm/src/fvm.pas` as the program (a stub for now), and `/app/fvm/build.sh` builds `/app/fvm/fvm`, which is run as `/app/fvm/fvm IMAGE` and writes the transcript to standard output. The box is offline and fpc with its own run-time units is all there is.

`/app/conformance` holds the vendor conformance suite. Grading compiles `src/fvm.pas` itself with `fpc -O2 -Mobjfpc -Sh` from `/app/fvm` (build.sh isn't used, and nothing but objects fpc compiled and its run-time units may reach the linker), then runs the binary on all 114 conformance images and on 61 held-back images built for other reader generations, with other word widths, limits and tick budgets and longer programs that mix the rules. All 175 transcripts have to match the sheet byte for byte. A run still going after 10 seconds fails; standard error and the exit code aren't looked at.

The graded runs happen as an unprivileged user with `/app/fvm` as the working directory, one process per image. The image is readable but not writable, no directory is writable, no other program on the box can be run, and the interpreter can't start a second process.
